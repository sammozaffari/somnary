# Somnary site UI kit

Two screens of the Somnary site, composed entirely from the system's components and tokens.

- `index.html` — interactive shell: home → (search result, situation, or card) → remedy page; fixed day/dusk toggle top-right (sets `data-theme="dusk"` on `<html>`).
- `HomePage.jsx` — slim header + nav, one-sentence hero over the search field (the page's largest object; earns attention by size and weight, not colour), tiered live results on the never-show-an-arbitrary-subset principle: an unambiguous query returns THE answer (tier 1: remedy + bucket + evidence bar + product-count cue), related routes (tier 2), the rest behind "More matches" (tier 3); category queries like the seeded "sleep" return problems + a browse-all-31 row, never a sample; products list only when the query names one (brand, dose, product word); misspellings get "Did you mean", no-match gets a plain state; every row type shares one 28px-lead grid with hairlines above group labels, quiet amber safety route, six situation cards, six remedy cards on real corpus numbers ordered by verifiable count, one honest stat with its "See the study" chip, plain-independence footer.
- `RemediesPage.jsx` — /remedies: every remedy grouped by bucket on the real distribution (melatonin alone at the top with the plain sparseness note; unknown holds 16 of 31 with a derived "N more pending data entry" row; bucket totals not yet audited render as placeholder rows). Fix + safety-flag filters, deliberate default sort (most evidence first — verifiable, then cited — because the page's job is answers, with A–Z for lookup). Every bucket badge links to "How we grade" (page not built yet — dead link). Use tags are descriptive of common use, pending audit. Includes the 1200×630 share image preview built from audited figures only.
- `GradePage.jsx` — /how-we-grade: the four grades first (readers arrive mid-question from a badge), then two-questions/product-score/verify/sources/recheck/errors/independence. The one page allowed real terminology — every term introduced plainly, technical detail behind Show/Hide folds. Deep links per section and per bucket (#works, #maybe, #unknown, #avoid); bucket badges on /remedies land on their own grade's card. Thresholds and ops specifics are marked [placeholder].
- `ProblemPage.jsx` — /problems/waking-at-3am: a Google landing page (reached from the homepage's "I keep waking at 3am" situation card or search results). One-line orientation for cold arrivals, [placeholder] explanation + calm doctor card, evidence-ordered remedy cards (nothing in the top bucket — stated), label-versus-studies for advice that doesn't hold up, CBT-I + non-supplement approaches, route into products. Includes the 1200×630 share image and a 390×720 above-the-fold phone preview. All medical/effectiveness copy is [placeholder] pending review.
- `ProductsPage.jsx` — the full melatonin product list, dense-list layout (C3): 104px square thumbnail (the BrandMark placeholder is the common case — two rows carry demo photos and sit level with the rest), brand/name/strength, the four checks labelled in place (2×2 dot + short word, no legend to scroll away), verdict pill (beneath the name on mobile — never dropped). Twelve fictional products across all four states: pass-all, partial, failing (0 of 4 — labelled, never hidden), label-known, not-in-database. Default sort: checks passed desc (our published criteria, never commercial), Brand A–Z alternative; form + independently-tested filters with counted, clearable, empty and single-result states. Includes a 390px six-row mobile preview. The same ProductListRow serves the products index and brand pages.
- `ProductPage.jsx` — the single-product decision narrative (no TOC/sidebar; section order is the argument; one "Where to buy ↓" jump with scroll-margin). Header: breadcrumb (system rule: every page, mobile truncates to "‹ Parent"), 288px square BrandMark slot top-aligned with the brand line, four text clusters (identity with price-per-night · verdict pill + one line · context with remedy link/bucket chip and factual dietary chips · meta). Sections: four checks each explained with why + study chips; how-to-take grid (the "how long until you know" cell is the quiet centrepiece); dose diagram (product marker vs studied band vs hatched market band, 0–10 mg); full label with No-known-concern / Worth-knowing / Documented-concern flags + allergen line + policy caveat; safety pointer to the remedy page; "a nudge, not a knockout" expectations; same-checks alternatives labelled by why-you'd-switch; sources + corrections box; where-to-buy identical regardless of score; keep-looking cards. No "What people report" — anecdote at the moment of purchase does the most damage. Two datasets via the bottom-right toggle: Dreamwell melts (4/4) and Dreamwell Sleep complex (1/4 — failed checks explained as plainly as passes, dose diagram replaced by "nothing to place on the scale"). All prices/protocols/label notes placeholder.
- `RemedyPage.jsx` — the remedy template all 31 remedies inherit, with two datasets: Melatonin (12/5/3, the full page) and Kava (5/0/0, the worst case). **Emptiness is derived from the data, never hardcoded** (`deriveEmpty`): sleep = 0 empties the explain/dose/label sections with data-derived absence sentences and dims their TOC entries; verifiable = 0 changes what "Does it work?" can say; `safetySerious` makes safety the dominant element (larger flag under the h1, "Serious safety concern." register, warning repeated above the product list). Products and papers never disappear — every product is listed and assessed on the same criteria, including ones Somnary advises against (locked decision). Sticky contents sidebar on desktop / collapsible on mobile; citations render as margin notes at their reference point on desktop and inline "See the study" chips on mobile. Toggle datasets with the fixed control bottom-right. All non-audit figures are marked [placeholder]; products are fictional demo entries.

All study data is illustrative placeholder shaped like the real corpus (melatonin: 12 papers, 5 measured sleep, 3 verifiable — audit figures; safety-flag text is a marked placeholder).
